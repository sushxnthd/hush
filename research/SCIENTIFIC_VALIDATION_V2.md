# Hush scientific validation v2

**Status:** preregistration / execution plan. No v2 result is claimed.  
**Updated:** 9 October 2026

## Why v2 is needed

Hush Scientific Superiority Protocol v1 passed its pre-specified gates on synthetic bounded-personalization tasks. That result is useful but narrow: the tasks are generated by Hush, the private-decision language is known in advance, and the primary exposure check is exact-value/path detection. The next claim should therefore be tested on externally originated tasks and traces that Hush did not design.

This document defines the next validation ladder and the analysis rules before any final holdout is scored.

## Research question

When an AI agent must complete a realistic user task with access to private context, does a Hush boundary:

1. preserve task completion;
2. reduce unnecessary private-context exposure across all observable agent channels; and
3. prevent private information from being encoded indirectly through actions or repeated interactions?

The target claim is deliberately narrower than “Hush is universally private” or “Hush is better than every competitor.”

## Evidence ladder

A result can advance only one rung at a time:

1. **Engineering invariants** — unit tests, mutation tests, and CI benchmarks.
2. **Internal mechanism evidence** — the current synthetic privacy/utility and reconstruction protocols.
3. **External task evidence** — a benchmark and holdout not authored or tuned by Hush.
4. **Independent reproduction** — a reviewer reruns the frozen protocol and inspects the artifacts.
5. **Named-competitor comparison** — the same external tasks, threat model, model configuration and budget are run against an actual comparator.

No rung implies the next one.

## Tier A — AgentDAM end-to-end data minimization

AgentDAM is the first external candidate because it evaluates realistic web-agent execution rather than asking a model abstract privacy questions. The official NeurIPS benchmark contains 246 tasks across controlled replicas of GitLab, shopping and Reddit-style environments, with task-success verification and privacy leakage labels.

### Frozen design

- Use the official AgentDAM release and record the exact upstream commit, environment image and license.
- Use every compatible task; do not choose a favorable subset.
- Freeze the task split and all private-data fixtures before running.
- Run three arms under the same agent backbone, tool permissions, temperature, seed policy and timeout:
  1. raw/full context;
  2. the strongest non-Hush minimization baseline available in the adapter;
  3. Hush-bounded context and Hush-approved actions.
- Do not compare Hush's score directly with the paper's model scores unless the backbone, task version and evaluator are identical.

### Primary endpoints

1. **Task success:** the benchmark's final-state verifier.
2. **Privacy leakage:** fraction of tasks with any unnecessary private-data use/disclosure in the action trace, using the benchmark's published evaluator.

Report both endpoints together. A privacy improvement that materially breaks task completion is not a successful Hush result.

### Secondary endpoints

- leakage volume and private-field categories;
- false-denial / unnecessary-block rate;
- number and type of approvals;
- action count, wall time and token/compute use;
- leakage by app and task family;
- exact versus paraphrased leakage;
- disagreement between automated and human adjudication.

### Analysis rule

Use paired task-level comparisons. Report the paired difference with an exact confidence interval and an exact McNemar test for binary leakage/success outcomes. Report bootstrap confidence intervals for continuous exposure and action-count measures. Keep all failures, timeouts and evaluator errors visible; a technical error yields no scientific claim for that task.

Because an LLM judge is not ground truth, independently double-code a blinded sample of traces with human raters and report agreement. Do not silently relabel judge disagreements as passes.

## Tier B — AgentLeak full-stack channel coverage

AgentLeak is relevant because output-only audits miss internal-channel leakage. Its benchmark covers final output, inter-agent messages, shared memory, tool arguments and other trace pathways across 1,000 scenarios.

### Frozen design

- Pin the public AgentLeak release and scenario identifiers.
- Use Hush's trace instrumentation to capture every channel the benchmark exposes.
- Compare the same three arms as Tier A where the task harness permits.
- Score each channel independently and also report an OR-aggregated “any channel leaked” endpoint.
- Do not treat a clean final answer as a clean run when an intermediate tool argument, memory write, log or inter-agent message contains the protected value.

### Primary endpoint

Paired change in **any-channel unnecessary protected-value exposure**.

### Secondary endpoints

Per-channel exposure, leakage category, action success, approval burden, and the fraction of violations that final-output-only auditing would miss.

This tier is the direct test of Hush's claim that privacy must be governed across agents and sinks, not only at the final answer.

## Tier C — AgentTell-style behavioral side channels

A bounded answer can be private in text yet still leak through behavior. AgentTell studies cases where a browser agent learns a secret on one site and reveals it by selecting a secret-specific action on another site.

### Hush-specific test

Construct a frozen action-equivalence suite in which:

- two or more public actions are equally valid for the user's stated task;
- only one action correlates with a hidden private field;
- the model receives the same task and public state in every arm;
- Hush may use the private field locally but must not select an action that needlessly encodes it;
- the trace records action identity, ordering, retries, denials and user-visible explanation.

Primary outcome is task success plus behavioral leakage. Timing, retry count and failure behavior are secondary side channels and must be reported rather than discarded.

## Tier D — Trace-Observable Privacy prototype

The internal TOP prototype in [TRACE_OBSERVABLE_PRIVACY.md](./TRACE_OBSERVABLE_PRIVACY.md) tests a failure mode that output-only audits can miss: a model can keep its text constant while selecting a secret-dependent action. In a 16-value synthetic domain, the prototype records 4 bits of leakage for an injective model-visible action trace, 0 bits for a constant opaque plan with local action selection, and 4 intentionally observable bits at the downstream provider sink while preserving the same synthetic task utility.

This is a mechanism check, not a v2 validation result. It does not cover timing, retries, failures, network observers, collusion, arbitrary plans, runtime integration or an external task benchmark. Tier D is included to make the sink boundary explicit before Tier A–C execution.

## Internal falsification upgrades

Before external scoring, expand the existing synthetic suite with negative controls that attempt to bypass the declared privacy language through:

- error messages and validation failures;
- approval prompts and denial explanations;
- receipts and diagnostics;
- JSON keys, paths, labels, Unicode/case variants and serialized numbers;
- action selection, retries and recipient choice;
- prompt-injected program metadata;
- correlated and non-uniform private priors;
- multiple simultaneous sinks and colluding agents;
- process restart, revision rewrite and provider switching.

A passing test requires the protected value to remain absent from every declared model-visible and trace-visible channel while the task outcome remains correct. Unsupported semantics must fail closed, not be silently scored as safe.

## Reproducibility package

Every external run must publish or retain:

- upstream benchmark URL, commit, license and task IDs;
- Hush commit and dependency lock;
- model name/version, inference settings and hardware;
- environment image and browser/runtime versions;
- frozen arm configuration and private-data fixture hash;
- raw redacted traces, evaluator outputs and adjudication decisions;
- exact scripts, random seeds and generated report;
- all failures, timeouts, excluded cases and reasons;
- independent reviewer notes and a rerun checksum.

No private user data, provider tokens or real-world account traces belong in the repository or public artifacts.

## Claim ladder after v2

The strongest claim allowed by each outcome is:

- Internal v1 only: “Hush outperformed the implemented synthetic baselines under Protocol v1.”
- External Tier A/B pass: “On the named external benchmark and frozen configuration, Hush reduced measured unnecessary exposure while preserving the reported task-success criterion.”
- Independent reproduction: add “independently reproduced.”
- Direct same-workload comparator: only then name the comparator.
- A failed or mixed tier must be reported as a limitation, not hidden behind a favorable aggregate.
