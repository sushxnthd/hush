# Hush product thesis

## Category

Hush is not a password manager, an MCP gateway, an enterprise policy engine, or a personal data vault by itself.

**Hush is the personal trust layer for AI.**

It should sit between a person and every AI system they use, governing both:

- what an AI may know
- what an AI may do

## Why this layer exists

Modern agent stacks split trust across many disconnected products:

- model providers own conversation context and memory
- password managers own credentials
- OAuth providers own delegated tokens
- MCP gateways own tool-call authorization
- operating systems own device permissions
- apps own their own audit histories

The user has no neutral place that answers, across all of them: **what has this AI learned about me, what authority does it have, and what happened on my behalf?**

## Core primitives

### 1. Disclosure

Every private fact should have a disclosure level rather than a binary shared/not-shared flag:

- presence
- boolean
- derived
- coarse
- masked
- exact

The system should prefer the least revealing level that still lets the task succeed.

### 2. Disclosure budget

Privacy is cumulative. Multiple harmless-looking facts can compose into a sensitive inference. Hush therefore tracks disclosure across a whole purpose/trajectory, not only per request.

Budgets are:
- agent-aware
- purpose-aware
- sink-aware
- cumulative
- auditable

### 3. Trust profile

Users explicitly place agents into trust profiles such as trusted, standard, limited, or blocked. Trust affects budgets and approval thresholds. Models must never be able to silently upgrade their own trust.

### 4. Authority Grant

Actions remain governed through signed, short-lived Grants bound to the user, agent, purpose, action, resource, limits, and expiry.

### 5. Receipts

Every material action and disclosure should produce a tamper-evident receipt generated by the enforcement layer, not by the agent.

### 6. AI Footprint

The primary consumer surface should answer:

- which agents know the most about me?
- what categories do they know?
- which external destinations received information?
- how much disclosure accumulated for each purpose?
- which agents have authority to send, buy, modify, or delete?

The footprint must summarize exposure without itself becoming another raw-secret database.

## Strategic wedge

The first wedge is **cross-agent visibility + control for AI power users**.

A user running Claude, ChatGPT, coding agents, browser agents, and MCP tools should be able to install one layer and see:

1. connected capabilities
2. high-risk authority
3. accumulated private-context exposure
4. pending approvals
5. a verifiable history of actions and disclosures

## What we should deliberately not race on first

- largest tool catalog
- password-vault replacement
- enterprise IAM console breadth
- proprietary OAuth replacement
- generic AI memory
- model training

Those are crowded and capital-intensive. Hush should integrate with them and own the user-level trust graph above them.

## Moat hypothesis

If Hush succeeds, its defensibility comes from the combination of:

- cross-provider integration graph
- user-specific trust graph
- longitudinal disclosure graph
- portable Grant/receipt format
- privacy-utility benchmark suite
- developer SDK adopted by agent builders
- brand trust with consumers

No individual feature is the moat. The moat is becoming the neutral place where users define their relationship with AI.
