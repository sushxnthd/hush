One private layer between you and every AI.

Hush keeps personal context under user control, lets AI query it through bounded semantics, carries approved memory across providers, routes tasks with privacy constraints, and brokers actions without exposing long-lived credentials.

What Hush does

01
Keep one encrypted context kernel.
Private records, metadata and reconstruction state are encrypted with authenticated encryption. Portable sync bundles contain ciphertext and opaque identifiers rather than readable personal context.
02
Answer semantic questions, not raw-context requests.
hush_private_query lets an agent describe the task and bounded decision it needs. Hush resolves the relevant private capability locally without revealing private paths or values to the agent.
03
Share memory across AIs without giving any AI unilateral ownership.
Agents can propose facts or preferences through hush_propose_memory. The value is not echoed back, and it enters the canonical shared Hush memory only after explicit local approval.
04
Route each task to the right model under privacy constraints.
The provider-neutral router can consider capability, cost, latency, locality, declared trust and whether a task needs no private context, bounded context or sanitized context. Tasks declared to require raw private context are rejected.
05
Broker authority instead of handing agents secrets.
Scoped grants, exact-action approvals, policy checks, secret references and tamper-evident receipts let agents request real actions while credentials remain outside the model-facing surface.
06
Move encrypted state across trusted devices.
Signed ciphertext-only sync envelopes, device identities, trust registration, revocation and conflict detection provide the current multi-device synchronization primitive without requiring a relay to decrypt user context.

The import layer currently normalizes Gmail, Calendar, Drive, Contacts and GitHub snapshots into the Context Kernel. Browser, desktop and mobile clients exist in the repository, but consumer-grade onboarding and production account authorization remain active product work.

The model is not the security boundary.

Hush enforces the boundary outside the model: encrypted local context, bounded semantic queries, realized privacy accounting, shared-memory approval, model routing, credential brokerage, exact approvals, grants, receipts and ciphertext-only sync. The current research is strongest on explicit output channels; timing, compromised hosts, bypass traffic, network metadata, covert channels and unmediated side effects remain outside the guarantee.

The boundary is fail-closed where it matters.

Unknown MCP tools can fail closed, raw secret material in tool arguments can be hard-denied, semantic private queries can be withheld when reconstruction risk is too high, memory writes require approval, stale sync writes conflict rather than silently overwrite, and exact approvals bind to the action that executes.
