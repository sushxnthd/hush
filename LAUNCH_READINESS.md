# Hush launch readiness

Updated 8 October 2026. Browser workspace: early access. Native runtime: release candidate. This document records evidence and concrete remaining work; it does not certify production readiness.

## Verified

- The requested light appearance is restored across the website, encrypted browser workspace, native dashboard and companion clients. Website verification covers 20 routes and 981 local references. Footage, stills, plan/deployment artwork, graph, pixel stream, engineering hardening and corrected statistics are preserved. The browser entry screen adapts the observed Supermemory console split layout to Hush’s passphrase, sample and encrypted-restore controls. The signed-in console dashboard was not accessible; exact dashboard replication remains pending an authorized reference. The previous hosted appearance evidence below remains pinned to its original candidate and is not relabeled as evidence for this UI revision.
- Website: 20 published routes, versioned local assets, working browser entry point, product walkthrough, setup, research, privacy, security, terms and help. The MCP page describes the native stdio/configuration path and authenticated HTTP alternative.
- Browser workspace: encrypted persistence, note editing, explicit memory approval, exact sharing preview, approved clipboard copy, backup/recovery and idle locking. No model requests or remote connections.
- 294 unit/security tests pass after the current hardening pass. The authenticated launch smoke covers 25 checks, including real stdio initialization/tool discovery, notification authority isolation, malformed/oversized HTTP bodies and healthy continued operation. All 13 engineering benchmark programs pass their bounded claims. These internal checks do not establish independent assurance or competitor superiority.
- Native hardening: normal startup requires local authentication and strict OS-keystore behavior; shipped launchers force production mode. Request/response buffers and upload times are bounded. SDK credentials cannot leave the configured origin through request paths or redirects. MCP has bounded queues, native JSON-only stdio output and no automatic authority retry. Resolved memory proposals discard duplicate plaintext values; proposal queue/value size and lifetime are capped.
- Local packaging, inventory/SBOM/checksum verification, exact bundled runtime boot, synthetic recovery and rollback pass. Portable candidates now include `hush-open`, `hush-mcp`, `hush-doctor` and dashboard launchers. Source cleanliness and an inventory digest are recorded; hosted packaging refuses dirty candidate source. Physical first-run/device/browser-client compatibility still needs validation.

## Provider references

- [Google installed-app OAuth](https://developers.google.com/identity/protocols/oauth2/native-app): desktop client type and loopback PKCE flow. Client secret is documented as optional for this flow.
- [GitHub OAuth authorization](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps): device flow must be enabled in app settings; its client secret is not required.
- [Apple Developer ID](https://developer.apple.com/developer-id/): signing and notarization for distribution outside the Mac App Store.
