# Threat model

Hush assumes AI agents, prompts, tool metadata, remote MCP servers, and downstream services may be buggy, compromised, over-privileged, or adversarial.

## Assets

- private user context
- credentials and delegated tokens
- authority to send, buy, modify, delete, publish, or transfer
- approval intent
- action/disclosure history

## Primary threats

### Prompt or tool injection
An agent or remote tool attempts to convince Hush to weaken policy, reveal secrets, or reinterpret user intent.

Mitigation direction: authorization decisions occur outside the model; exact-call approvals are hash-bound; hard denies cannot be overridden by normal approval.

### Credential exfiltration
Secrets are placed into model context or tool arguments.

Mitigation direction: secret detection, redaction, vault-backed credential brokerage, and hard deny for credential-like MCP arguments.

### Permission drift
An approval for one action is reused for a materially different action.

Mitigation direction: short-lived scoped Grants, exact-action hashes, use counts, expiry, and replay protection.

### Cumulative privacy leakage
Many individually acceptable disclosures combine into a sensitive profile.

Mitigation direction: disclosure levels, marginal information accounting, cumulative purpose budgets, sink budgets, and cross-agent aggregation.

### Agent collusion
Several agents working on the same purpose split disclosures to evade a per-agent limit.

Mitigation direction: purpose/sink exposure is aggregated across agents while marginal information remains agent-aware.

### Untrusted MCP metadata
A malicious server falsely marks a destructive tool as read-only or safe.

Mitigation direction: annotations are treated as hints and require explicit upstream trust before they can influence automatic authorization.

### Audit tampering
An agent tries to rewrite or omit evidence of what happened.

Mitigation direction: receipts are generated by the enforcement layer and chained tamper-evidently.

## Out of scope for the current alpha

- compromise of the host operating system or Node.js runtime
- hardware side channels
- production-grade secure key storage
- malicious code with direct filesystem/process access outside Hush
- traffic that bypasses Hush entirely
- formal privacy guarantees from the synthetic privacy-cost scale
- guarantees that the heuristic MCP exposure scanner identifies all dangerous tools

## Security principle

**The model can request authority; it cannot define its own authority.**
